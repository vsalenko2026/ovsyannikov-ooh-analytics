# Выгрузка Вордстата через API

Скрипт заменяет ручной сбор брендового спроса для отчёта об эффективности
наружной рекламы «Овсянникова». Было — около 80 открытий веб-интерфейса перед
каждым отчётом. Стало — одна команда: 72 вызова API, 1,44 ₽, сырые ответы на
диске, два файла на выходе.

```
config.yaml       периметр: фразы, даты, период, устройства
regions.yaml      справочник: наше название -> ID Вордстата -> кампания/контроль
run.py            единственная точка входа
ws/               код: api, periods, fetch, build, reconcile, regions
raw/YYYY-MM-DD/   сырые ответы, по файлу на вызов
output/YYYY-MM-DD/ wordstat_long.csv, wordstat_wide.xlsx, таблица сверки
tests/            34 теста, сеть не нужна
```

## Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env          # вписать ключ и folderId
python3 run.py plan           # что будет выгружено и почём — без обращений к API

python3 run.py regions fetch-tree   # разово: справочник регионов
python3 run.py regions resolve      # разово: проставить region_id
python3 run.py probe-regions        # разово: проверить, суммирует ли API регионы

python3 run.py fetch          # выгрузка (кэш, ретраи, лог стоимости)
python3 run.py build          # wordstat_long.csv + wordstat_wide.xlsx
python3 run.py reconcile --manual ручная_выгрузка.csv
```

`fetch` перезапускаемый: уже полученные ответы берутся из кэша, после обрыва
достаточно повторить команду. Тесты — `python3 -m unittest discover -s tests -t .`

## Доступы

Заводит заказчик, самостоятельно не создаём. Нужны четыре вещи:

| Что | Куда |
|---|---|
| Аккаунт Yandex Cloud / AI Studio с привязанным платёжным аккаунтом | — |
| Сервисный аккаунт с ролью `search-api.webSearch.user` | — |
| API-ключ этого сервисного аккаунта (начинается с `AQVN…`) | `YANDEX_API_KEY` в `.env` |
| `folderId` каталога, где живёт сервисный аккаунт | `YANDEX_FOLDER_ID` в `.env` |

`.env` в `.gitignore`, в коде и в репозитории ключей нет. Скрипт читает
переменные окружения и, если их нет, останавливается с понятным сообщением.

## Источник данных

Wordstat — сервис внутри Yandex Search API v2 (AI Studio). Веб-парсинг не
используется. Авторизация — заголовок `Authorization: Api-Key <ключ>`,
`folderId` обязателен в теле каждого запроса.

| Метод | Путь | Где используется |
|---|---|---|
| `GetDynamics` | `POST /v2/wordstat/dynamics` | основной сценарий, `run.py fetch` |
| `GetRegionsTree` | `POST /v2/wordstat/getRegionsTree` | `run.py regions fetch-tree`, не тарифицируется |
| `GetTop` | `POST /v2/wordstat/topRequests` | `run.py top` — разбор омонимов |

## Принятые решения

**Область, а не город.** `meta.level: oblast` в `regions.yaml`. Периметр кампании
задан городами, но контрольная группа изначально набрана областями, а сравнивать
город с областью нельзя: уровень должен быть одинаковым для обеих групп. Города
сохранены в поле `cities` — если заказчик решит иначе, меняется справочник, не код.

**Один регион на вызов.** По документации `regions[]` — «список регионов, из
которых сделан запрос»: ответ приходит одним рядом, без разбивки. Проверяется
эмпирически командой `probe-regions`: она делает три вызова (регион A, регион B,
A+B) и сравнивает суммы. Если подтвердится суммирование — текущая схема верна;
если нет, сырые ответы останутся в `raw/probe/` для разбора. Разбивку по регионам
умеет отдельный метод `GetRegionsDistribution`, но он даёт срез, а не динамику.

**Границы недель не пересобираются.** Скрипт не строит недельную сетку сам. Он
берёт дату из ответа API и определяет, с какого края недели она проставлена
(`week_anchor: auto`): все даты понедельники — начало недели, все воскресенья —
конец. Смешанный набор — сборка останавливается с ошибкой, а не достраивает
границы наугад. Определённый якорь пишется в `build.json` и печатается в консоль.

**Незакрытая неделя.** По умолчанию не запрашивается: `toDate` выравнивается на
конец последней **закрытой** недели. Если включить `series.include_current_period`,
неполная неделя попадёт в выгрузку с `is_partial=1` в CSV и подсветкой в XLSX.
Молча в расчёт множителей она не попадает ни при каком режиме.

**Омонимы не фильтруются.** По Орловской области запрос со словом «купить»
собирает шум от названия региона. Скрипт выгружает как есть — фильтрация на
этапе анализа, чтобы сырые данные оставались сырыми. Разобрать структуру шума:
`python3 run.py top --phrase "овсянников купить" --region "Орловская область"`.

## Форматы выгрузки

**`output/YYYY-MM-DD/wordstat_long.csv`** — длинный формат, основной для анализа:

```
date, week_start, week_end, phrase, region_name, region_id, region_type, device, count, share, is_partial
```

`is_partial` — колонка сверх ТЗ: 1 означает, что неделя на момент выгрузки не
закрыта. Кодировка UTF-8 с BOM, разделитель — запятая.

**`output/YYYY-MM-DD/wordstat_wide.xlsx`** — широкий, для глазной проверки:
лист на фразу, строки — недели, колонки — регионы. Кампания идёт первой, по
убыванию числа экранов, затем контроль. Незакрытые недели подсвечены.

Каталог результата назван датой прогона и не перезаписывается: повторная сборка
поверх требует `--force`.

## Сверка с ручной выгрузкой

Обязательный этап приёмки. Пока не пройден — скрипт не считается готовым.

```bash
python3 run.py reconcile --manual ручная_выгрузка.csv
```

Ручная выгрузка — таблица (csv, tsv или xlsx) с четырьмя колонками; заголовки
распознаются по названию, порядок неважен:

| фраза | регион | дата | частота |
|---|---|---|---|
| овсянников мыло | Ярославская область | 2026-07-13 | 41 |

В колонке «регион» можно писать город («Ярославль») — сопоставится через
`cities` из справочника. Дата — любой день недели, приводится к её началу.

На выходе — `сверка_с_ручной_выгрузкой.md` и `.csv`: неделя, значение ручное,
значение из API, расхождение в процентах. Пороги:

| Условие | Итог |
|---|---|
| расхождение до 2% на отдельных неделях | приемлемо, фиксируется здесь, в README |
| медиана расхождений > 1% | СТОП |
| отдельное расхождение > 10% | СТОП |
| суммарное отношение API/ручная вне [0,98; 1,02] | СТОП |
| строка ручной выгрузки не нашла пары | СТОП |

Коэффициентами не подгонять. Разбираться в таком порядке: операторы в фразе,
трактовка словоформ, ID региона в справочнике, границы недель.

### Признанные расхождения с веб-интерфейсом

Раздел заполняется по результату первой сверки — пока доступов нет, он пуст.

## Периметр

24 региона: 17 кампании (19 городов, свёрнуты в субъекты федерации) и 7
контрольных. Источник — фактический список размещения на 17.07.2026. Ярославская
область идёт отдельной строкой: `campaign_start: 2026-06-04`, у остальных
`2026-07-17`.

Три фразы ядра — `овсянников мыло`, `овсянников косметика`, `овсянников купить`.
Расширенный список (`овсянников крем`, `овсянников сайт`, `ovsyannikovsoap` и
прочие) добавляется в `config.yaml` без правки кода; `овсянников отзывы` не
берём — однофамилец.

Прогон: 3 фразы × 24 региона × 1 срез устройств = 72 вызова.

## Подводные камни API

Проверено по документации сервиса и разборам; часть подтвердится только на
боевых доступах.

- `toDate` обязан быть последним днём периода, иначе `InvalidArgument: The to
  field value should be the last day of the week`. Выравнивание делает
  `ws.periods.period_end`.
- `period` — только с префиксом: `PERIOD_WEEKLY`, не `WEEKLY`.
- `count` приходит **строкой** (особенность proto для int64) — приводится к int
  в `ws.api.dynamics_rows`.
- `GetDynamics` принимает только оператор `+`. Кавычки, `!`, `[]`, `()`, `|`
  отвергаются — скрипт проверяет фразу до вызова и не тратит квоту.
- Лимит частоты — порядка 5–10 запросов в секунду. Пауза между вызовами
  `api.pause_seconds` (по умолчанию 0,3 с), ретраи с экспоненциальной задержкой
  2 / 4 / 8 / 16 с, не более `max_attempts` попыток.
- Вызовы, упавшие с 5xx, 401, 403 и 429, не тарифицируются и в стоимость прогона
  не входят.
- Тариф в логе взят из ТЗ: 0,02 ₽ за вызов (`api.price_per_call_rub`). Есть
  сведения, что Wordstat в составе AI Studio сейчас бесплатен — проверить по
  первому счёту и, если так, поставить 0.

## Что осталось

- **Первый боевой прогон и сверка.** Требуют доступов; без них `regions.yaml`
  лежит с незаполненными `region_id`, и `fetch` до сверки не запускается.
- **Уровень Тюменской области.** В дереве Яндекса ХМАО и ЯНАО могут быть её
  дочерними узлами. При `regions resolve` проверить, какой узел выбран, и
  зафиксировать решение — иначе в ряд попадёт спрос двух округов сверх периметра.
- **Число экранов.** В досье 114 экранов основной программы плюс 7 в Ярославле,
  но таблица фактического размещения даёт в сумме 117 (110 без Ярославля).
  На выгрузку не влияет — `screens` в справочнике только для порядка колонок,
  но при сверке периметра расхождение стоит закрыть.
- **Запуск по расписанию** (Cloud Function + таймер + уведомление в телеграм) —
  отдельная задача второго шага, здесь сознательно не делается.
