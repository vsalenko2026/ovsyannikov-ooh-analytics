# Аналитика наружной рекламы «Овсянников»

Оценка эффективности OOH-кампании по методике difference-in-differences:
динамика брендового спроса в городах размещения сравнивается с динамикой в
контрольных регионах без размещения.

```
чистый эффект = (кампания_после / кампания_до) / (контроль_после / контроль_до)
```

## Что в репозитории

| Каталог | Что |
|---|---|
| `wordstat/` | выгрузка брендового спроса из Яндекс Вордстата через официальный API |

Расчёт множителей и сборка HTML-отчёта пока живут вне репозитория —
переезжают следующими шагами.

## Выгрузка Вордстата

Заменяет ручной сбор: было около 80 открытий веб-интерфейса перед каждым
отчётом, стало — одна команда, 72 вызова API, сырые ответы на диске и два
файла на выходе.

```bash
cd wordstat
pip install -r requirements.txt
cp .env.example .env                # вписать ключ и folderId
python3 run.py plan                 # что будет выгружено и почём, без обращений к API

python3 run.py regions fetch-tree   # разово: справочник регионов
python3 run.py regions resolve      # разово: проставить region_id
python3 run.py probe-regions        # разово: проверить, суммирует ли API регионы

python3 run.py fetch                # недельный ряд: кэш, ретраи, лог стоимости
python3 run.py build                # wordstat_long.csv + wordstat_wide.xlsx
python3 run.py reconcile --manual ручная_выгрузка.csv

python3 run.py fetch --period PERIOD_DAILY   # дневной ряд, глубина ~60 суток
python3 run.py build --period PERIOD_DAILY
python3 run.py top-export                    # топ вложенных запросов и ассоциаций
```

Три вида выгрузки, по 216 вызовов каждая: недельный ряд (основа для расчёта
множителей), дневной срез (форма отклика внутри кампании — глубже 60 суток
Вордстат по дням не отдаёт, окна «до» там нет) и топ слов за 30 дней (раздел
«что именно ищут» и разбор омонимов по Орловской области).

Периметр — 24 региона: 17 кампании (19 городов) и 7 контрольных, девять
брендовых фраз. Ядро метрики — `овсянников мыло`, `овсянников косметика`,
`овсянников купить`.
Меняется в `wordstat/config.yaml` и `wordstat/regions.yaml`, код при этом
не трогается.

Подробности — методика, принятые решения, подводные камни API, форматы
выгрузки и процедура приёмочной сверки — в [`wordstat/README.md`](wordstat/README.md).

## Состояние

- Скрипт написан и покрыт тестами: `cd wordstat && python3 -m unittest discover -s tests -t .`
- Не выполнено до получения доступов Yandex Cloud: заполнение `region_id`
  в справочнике и приёмочная сверка с ручной выгрузкой.
- Данные выгрузок (`wordstat/raw/`, `wordstat/output/`) в git не попадают.

## Доступы

Пошаговая инструкция — [`wordstat/README.md`, раздел «Доступы»](wordstat/README.md#доступы-что-сделать-по-шагам):
организация в AI Studio, платёжный аккаунт, API-ключ, `folderId`, роль
`search-api.webSearch.user` и проверочный запрос. Ключ и каталог кладутся в
`wordstat/.env`, который в `.gitignore`; в репозитории их нет и быть не должно.
