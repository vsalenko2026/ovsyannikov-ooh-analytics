# Овсянников · OOH-аналитика · состояние на 28.10.2026

Документ описывает состояние проекта: откуда берутся данные, что уже
посчитано, как работает автоматическая выгрузка и чего не хватает.
Построчные данные клиента (CRM, Ozon) здесь не хранятся — они передаются

## 1. Задача и метод

Клиент — «Овсянников» (парфюмированная косметика и мыло, B2B-опт,
сайт ovsyannikovsoap.ru, линия «Тайный советник»). С 17 июля 2026 идёт
наружная реклама в 17 областях. Нужно регулярно мерить эффект: вырос ли
спрос, трафик, заявки и продажи именно там, где висели баннеры.

**Difference-in-differences.** 17 областей кампании против 7 контрольных
без баннеров:

```
чистый эффект = (кампания_после / кампания_до) / (контроль_после / контроль_до)
```

Контроль отделяет эффект баннеров от сезонности и общего роста бренда.

**Окна:** «до» — по 16.07.2026, «после» — с 17.07.2026. Ярославская
область стартовала 04.06, поэтому ключевые цифры дублируются
«без Ярославля».

## 5. Автоматическая выгрузка

```
wordstat/
  config.yaml      8 фраз, периоды, окна
  regions.yaml     24 области с ID Вордстата
  run.py           plan / fetch / build / top-export / reconcile
  ws/              api.py, config.py, fetch.py, build.py, top.py, periods.py
  tools/week.sh    сценарий, который запускает рутина
  tests/           63 теста, без сети
  raw/ output/     выгрузки по датам, версионируются
```

**Фразы:** овсянников мыло · косметика · купить · крем · сайт ·
тайный советник · ovsyannikovsoap · ovsyannikov.

Убраны «образцы» (везде нули) и «отзывы» (омоним: в контроле частота
в 0,23 раза от ожидаемой — ищут другого Овсянникова).

**Расписание.** Работает одна рутина `trig_01HFsgtSzD9cs6iXW9FSDbgh`,
cron `0 9,15 * * *`, окружение `env_01NAS1u17zHsu8zkHeXTFJaF`, команда
`bash wordstat/tools/week.sh`. Шесть прежних переименованы в
`[выключено] …` и отключены.

**Почему месяц выгрузки молча не работали.** В рутине не был привязан
репозиторий (`sources` пустой), git-прокси отбивал push с 403, а
`add_repo` в сессиях рутины недоступен. Привязка репозитория к рутине
делается **только через интерфейс claude.ai** — скриптом это невозможно.
Если выгрузки снова перестанут появляться в git, проверять нужно это
в первую очередь.

Вторая причина была в коде и исправлена: квотный отказ 429 считался
временным, скрипт уходил в пять попыток с паузами на каждый вызов, через
полчаса падал, и `set -e` убивал его до коммита — скачанные данные
терялись. Теперь 429 завершает попытки сразу, есть предохранитель на
5 подряд неудач, коммит делается при любом исходе.

### Доступ к API

Яндекс Search API v2 (AI Studio), эндпоинты
`https://searchapi.api.cloud.yandex.net/v2/wordstat/{dynamics|topRequests|getRegionsTree}`.
Ключ и `folderId` живут в credentials окружения, прокси подставляет
заголовок `Authorization: Api-Key …`. В репозитории ключа нет и быть не
должно; код читает его из окружения.

### Грабли API

- `count` приходит строкой, не числом.
- `toDate` обязан быть последним днём периода.
- `period` требует префикс: `PERIOD_WEEKLY`, не `WEEKLY`.
- Операторы `!` `""` `[]` `()` `|` работают только с `PERIOD_DAILY`;
  в неделях и месяцах допустим лишь `+`.
- Точки с нулевой частотой приходят без поля `count` — не как нуль.
- Детализация по дням — около 60 дней назад, недели — с 2018 года.
- `folderId` обязателен в теле каждого запроса.

Полный цикл — 648 вызовов, примерно 20 минут; лимит 100 вызовов в час
на практике не упирался.

## 6. Методические решения

1. Область, не город — иначе частоты Вордстата не хватает.
2. Один регион на вызов — пакетные запросы смешивают регионы.
3. Незакрытый период не берём: последняя неполная неделя выкидывается,
   иначе ряд падает на ровном месте.
4. Якоря недель не достраиваем — берём те, что отдаёт API.
5. Омонимы не фильтруем, кроме выброшенной фразы «отзывы».
6. Дедупликация CRM по ключу «Название сделки + Дата создания», из дублей
   первая воронка по алфавиту: 1 361 → 1 348 строк, всего 13 дублей
   (в прошлый раз 147 — источник стал чище).
7. Склейка Ozon по «Номеру отправления», при совпадении побеждает строка
   из более свежей выгрузки. 1 006 отправлений (2,9 %) меняли статус между
   выгрузками: 703 «Доставляется» → «Доставлен», 134 → «Отменён»; по тем
   же отправлениям расходится 143 единицы товара. Поэтому склейка
   обязательна — брать только последнюю выгрузку нельзя.

## 7. Чего не хватает

1. **Метрика до 17 июля** — проверить счётчик 106615828. Если истории
   нет, блок трафика идёт как текущий срез без множителя, и это нужно

2. **Дата отсечки отчёта.** Источники кончаются в разные дни: Вордстат
   07.10, CRM 24.10, Ozon 28.10. Нужна одна дата, либо подпись у каждого
   блока — иначе читатель сравнивает несравнимое.
3. **Заявки после 20.10** — проверить при следующей выгрузке CRM.
4. **Пакет от 19.08.2026** собирался в другом чате и в репозиторий не
   попадал; на Google Диске и в подключённых папках его нет. Если нужен
   как база сравнения — приложить заново.

## 8. Что можно автоматизировать дальше

**Метрика по API.** Нужно добавить `api-metrika.yandex.net` в разрешённые
домены окружения и положить в credentials OAuth-токен с заголовком
`Authorization: OAuth <token>`. Дальше тот же механизм, что у Вордстата.

**Выгружатель под другую тему** делается копией папки `wordstat/` с
заменой `config.yaml` и `regions.yaml` — код темы не знает.
